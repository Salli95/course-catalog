## 📌 Краткий словарик терминов (шпаргалка на 2 минуты)

Перед тем как разбирать проект, вот простые объяснения главных слов:

* **Node.js** — среда, которая запускает JavaScript на компьютере/сервере (без браузера).
* **React** — библиотека, где весь интерфейс собирается из кирпичиков-конструкторов (**компонентов**).
* **Next.js** — мощный фреймворк поверх React и Node.js. Он объединяет сервер (бэкенд) и страницы сайта (фронтенд) в один проект.
* **Рендеринг (Rendering)** — процесс сборки: когда программный код React превращается в итоговый HTML-текст, понятный браузеру.
* **Server Components (RSC, серверные компоненты)** — компоненты, которые собираются **только на сервере в Node.js**. Браузер получает уже готовый чистый HTML без лишнего JavaScript. В проекте это 99% всех файлов.
* **Client Component (клиентский компонент)** — компонент, который загружается в браузер и может обрабатывать действия пользователя (клики, ввод текста). Помечается строчкой `"use client"`. У нас это **только кнопка лайка** (`LikeButton.tsx`).
* **Гидратация (Hydration)** — процесс, когда браузер берет готовую HTML-картинку с сервера и «оживляет» интерактивную кнопку лайка с помощью JS.
* **SSG (Static Site Generation)** — предварительная генерация: страницы курсов создаются на сервере заранее во время сборки (`npm run build`) и сохраняются файлами. Поэтому они открываются мгновенно.
* **SSR (Server-Side Rendering)** — сервер генерирует страницу прямо в момент обращения пользователя (например, каталог `/courses` фильтрует курсы при каждом запросе).
* **Query-параметры (SearchParams)** — параметры поиска в конце ссылки: `?q=react&type=elective`. Позволяют делиться ссылкой с уже примененными фильтрами.
* **Props (пропсы)** — параметры, которые мы передаём внутрь компонента (как аргументы в функцию: например, название курса, количество лайков).
* **State (состояние / useState)** — переменная внутри компонента, изменение которой заставляет React перерисовать этот кусочек интерфейса.
* **localStorage** — хранилище прямо внутри браузера пользователя. Позволяет сохранять данные (наши лайки) даже после закрытия вкладки или перезагрузки страницы (F5).

## 🧠 Как взаимодействуют Node.js, React и Next.js

Новичку легко запутаться: «Где здесь бэкенд, а где фронтенд?». В Next.js они работают в одной связке:

```
[ Пользователь в браузере ]
           │
           │ 1. Вводит адрес: http://localhost:3000/courses?q=React
           ▼
[ СЕРВЕР (Node.js + Next.js) ]
  ├── 1. Читает URL-параметры (?q=React)
  ├── 2. Загружает массив курсов из lib/courses.ts (с задержкой 300 мс)
  ├── 3. Фильтрует курсы через функцию в lib/catalog.ts
  ├── 4. Берет React-компоненты (CourseCard, разметку) и ПРЕВРАЩАЕТ ИХ В HTML ТЕКСТ
  └── 5. Отдает готовый HTML браузеру
           │
           ▼
[ БРАУЗЕР ПОЛЬЗОВАТЕЛЯ ]
  ├── Показывает готовую страницу мгновенно (потому что это готовый HTML)
  └── Оживляет единственную интерактивную деталь: кнопку лайка (LikeButton)
```

### В чём фишка такой схемы?
В обычных React-приложениях (например, старый Create React App) браузер сначала скачивал огромный пустой файл и гигантский JavaScript, и только потом телефон или ноутбук пользователя начинал собирать страницу.  
В **Next.js App Router** сервер делает всю тяжелую работу сам, а браузеру отдает лёгкий готовый HTML. Сайт работает в разы быстрее, а поисковики (Google, Яндекс) идеально видят весь контент.

## 📂 Структура файлов проекта (по полочкам)

### 1. Серверная логика и данные (`lib/`) — это чистый Node.js / TypeScript
* `lib/courses.ts` — «база данных» проекта. Здесь лежит массив с 6 курсами и функции `getCourses()` и `getCourse(id)` с задержкой 300 мс.
* `lib/catalog.ts` — функции фильтрации и сортировки `filterCourses(courses, query)`. Здесь нет никакого HTML, только чистая математика и алгоритмы работы с массивами.
* `lib/course-details.ts` — подробное описание каждого курса: цели обучения, список из 4 тем и пререквизиты (что нужно знать перед началом).

### 2. Компоненты (`components/`)
* `components/CourseCard.tsx` — **Серверный компонент** карточки курса. Карточка полностью кликабельна (переходит на страницу курса), а в правом нижнем углу содержит компактную кнопку лайка.
* `components/LikeButton.tsx` — **Единственный клиентский компонент** (`"use client"`). Отвечает за лайки:
  * Имеет два вида: компактный (для карточек в каталоге) и полный (большая кнопка на странице самого курса).
  * Сохраняет клики в `localStorage` (ключ `course_likes_{id}`), чтобы лайки не пропадали после перезагрузки F5.
  * Синхронизирует значение в реальном времени между всеми карточками через события `CustomEvent`.

### 3. Страницы (`app/`)
* `app/layout.tsx` — «обёртка» для всех страниц сайта. Здесь находится непрозрачная белая шапка с логотипом, меню навигации и подвал (футер).
* `app/page.tsx` — Главная страница сайта: красивый приветственный баннер, блок популярных курсов с возможностью ставить лайки сразу, и список направлений.
* `app/about/page.tsx` — Страница «О проекте» с целями работы и описанием стека.
* `app/courses/page.tsx` — Страница каталога курсов. Содержит поисковую строку, радиокнопки выбора типа курса, сортировку и вывод карточек `CourseCard`.
* `app/courses/[id]/page.tsx` — Страница одного конкретного курса (папка `[id]` означает, что адрес динамический, например `/courses/modern-frontend`).
* `app/courses/loading.tsx` и `app/courses/[id]/loading.tsx` — анимация скелетона на время загрузки.
* `app/courses/not-found.tsx` — экран 404, если курса с таким ID не существует.

## 🧪 Как устроены автоматические тесты (`tests/catalog.test.mjs`)

Запуск тестов выполняется командой:
```bash
npm test
```
Тесты написаны с помощью встроенного в Node.js модуля `node:test` (не требует установки лишних пакетов). Всего 6 тестов:
1. **Поиск без учета регистра и с пробелами:** проверяет, что при вводе `"  REACT  "` корректно находится нужный курс.
2. **Комбинация фильтра и поиска:** проверяет, что при противоречивых фильтрах (ищем React, но фильтр «Только элективы») система возвращает пустой список, а не ломается.
3. **Иммутабельность сортировки:** проверяет, что сортировка по лайкам/алфавиту не портит исходный массив в памяти.
4. **Защита от дублей query-параметров:** если в URL передали `?q=a&q=b`, берется первое значение, а при неизвестной сортировке сайт просто показывает порядок по умолчанию.
5. **Целостность данных по ТЗ:** сверяет все 6 курсов, кредиты, лайки и обязательное наличие ровно 4 тем в каждом курсе.
6. **Контроль клиентской границы:** скрипт сканирует все файлы в `app/`, `components/`, `lib/` и строго проверяет, что `"use client"` есть **только** в `components/LikeButton.tsx`.

## 🎓 Шпаргалка для защиты перед преподавателем

### Вопрос 1: «В чём разница между Server и Client Components?»
> **Ответ:**  
> По умолчанию в App Router все компоненты серверные (RSC). Они исполняются на сервере, имеют прямой доступ к данным и компилируются в чистый HTML.  
> Клиентские компоненты (с директивой `'use client'`) передаются в браузер в виде JavaScript-кода. Только они могут использовать хуки (`useState`, `useEffect`) и обрабатывать события пользователя (клики, ввод). Мы изолировали интерактивность так, чтобы клиентским был только компонент кнопки лайка.

### Вопрос 2: «Как работает поиск и фильтрация без клиентского useState?»
> **Ответ:**  
> Фильтрация построена на нативных возможностях веба — форме и параметрах адресной строки (URL search params). Форма отправляет GET-запрос на `/courses?q=...&type=...`. Серверный компонент страницы считывает `searchParams`, на сервере фильтрует массив данных и возвращает браузеру готовый HTML. Это экономит ресурсы браузера и позволяет делиться готовой ссылкой на отфильтрованный список.

### Вопрос 3: «Зачем нужна функция generateStaticParams в странице курса?»
> **Ответ:**  
> Это механизм SSG (статической генерации страниц). Во время сборки проекта (`npm run build`) Next.js заранее опрашивает `generateStaticParams()`, получает ID всех 6 курсов и сразу генерирует для них готовые HTML-файлы. Благодаря этому страницы курсов открываются мгновенно, без задержек на обращение к серверу.

### Вопрос 4: «Как сохраняются лайки?»
> **Ответ:**  
> Кнопка лайка `LikeButton.tsx` использует хук `useState` для моментального обновления цифры на экране и сохраняет текущее значение в `localStorage` браузера по ключу курса. При перезагрузке страницы (F5) компонент считывает сохранённое число из `localStorage`, поэтому лайки не сбрасываются.

### Вопрос 5: «Что изменилось в Лабораторной работе №3 (shadcn/ui и стилизация)?»
> **Ответ:**  
> 1. Инициализирован генератор компонентов shadcn/ui (`components.json`, `lib/utils.ts` с функцией `cn`).
> 2. Добавлены компоненты `Card` и `Button` в папку `components/ui/`. Они остаются Server Components (без `"use client"`).
> 3. Компонент карточки `CourseCard.tsx` переписан с использованием `Card`, `CardHeader`, `CardTitle`, `CardContent`, `CardFooter`.
> 4. Сетка карточек в каталоге и на главной сделана адаптивной (Mobile-first): 1 колонка на смартфонах, 2 на планшетах (`sm:`), 3 на компьютерах (`lg:`).
> 5. Проект оформлен в аккуратную изумрудно-зеленую палитру с мягким фоном страницы.

## 🎨 Подробно о Лабораторной работе №3 (Что именно было изменено)

В Лабе 3 стояли 3 основные задачи по лекции 3 («UI Systems: Tailwind CSS and shadcn/ui»):

### 1. `shadcn/ui init + add Button and Card`
* **Что сделано:** Создана конфигурация `components.json`, настроена утилита `lib/utils.ts` с функцией `cn()` для слияния классов Tailwind.
* **Добавлены компоненты:**
  * `components/ui/card.tsx` — карточка с суб-компонентами (`CardHeader`, `CardTitle`, `CardContent`, `CardFooter`).
  * `components/ui/button.tsx` — кнопка на базе библиотеки `class-variance-authority` (cva) с готовыми вариантами: `default`, `outline`, `ghost`, `secondary`.
* **Архитектурный нюанс:** Эти компоненты НЕ содержат `"use client"`. Они остаются Server Components, поэтому строгий автотест №6 на единственную клиентскую границу (`LikeButton.tsx`) успешно проходит.

### 2. `rewrite CourseCard using Card/Button`
* **Что сделано:** В `components/CourseCard.tsx` убраны самодельные `div`. Теперь карточка собирается из официальных кирпичиков shadcn:
  ```tsx
  <Card className="group relative flex flex-col justify-between border-emerald-100 hover:border-emerald-300 hover:shadow-md transition">
    <CardHeader>
      <CardTitle>{title}</CardTitle>
    </CardHeader>
    <CardContent>
      <p>{description}</p>
    </CardContent>
    <CardFooter>
      <span>{credits} кредитов</span>
      <LikeButton courseId={id} initialLikes={likes} compact />
    </CardFooter>
  </Card>
  ```
* **Кнопка лайка:** В `components/LikeButton.tsx` кнопка переведена на shadcn `Button` с вариантом `variant="ghost"` для карточки и `variant="outline"` для страницы курса.

### 3. `make the card list responsive`
* **Что сделано:** По принципу Mobile-first со слайда 12 лекции сетка карточек настроена через:
  ```html
  <div className="grid grid-cols-1 sm:grid-cols-2 lg:grid-cols-3 gap-5">
  ```
  * **Экран смартфона (< 640px):** 1 колонка на всю ширину.
  * **Планшет (>= 640px):** 2 колонки (`sm:grid-cols-2`).
  * **Ноутбук/ПК (>= 1024px):** 3 колонки (`lg:grid-cols-3`).

### 4. Цветовая палитра (Изумрудно-зеленый оттенок)
* В `app/globals.css` настроена мягкая зеленоватая гамма: фон страницы `--background: #f4fbf7`, основной акцент `--primary` в изумрудном спектре.
* Все кнопки, ссылки, теги направлений и бейджи переведены в гармоничные классы `emerald` (`emerald-600`, `emerald-50`, `border-emerald-100`), сохраняя легкий, естественный студенческий стиль без вычурности.

### 5. Настоящая мобильная версия (Mobile UX)
* **Раскрывающийся навбар (Burger Menu):** На узких смартфонах (< 640px) ссылки навигации раньше накладывались на логотип. Теперь на телефонах выводится аккуратная кнопка-бургер на базе нативного HTML5 `<details>/<summary>` (без нарушения правила серверных компонентов и без `"use client"`). При нажатии выпадает аккуратное мобильное меню.
* **Компактные карточки на телефоне:** Карточки получили отзывчивые отступы (`p-3.5 sm:p-5`), уменьшенные размеры шрифтов для мобильных экранов (`text-sm sm:text-base`) и компактные футеры (`py-2 sm:py-3`), благодаря чему они не занимают весь экран смартфона и выглядят аккуратно.
